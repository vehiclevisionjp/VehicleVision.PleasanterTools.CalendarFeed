# 実機検証結果

`tools/pleasanter-testenv`（Pleasanter **1.5.8.1** ＋ SQL Server 2025）で確認した事実。
**検証日 2026-10-12。** ソースの読みや Questionnaire の 1.5.7.0 での結果に頼っていた仮定を、対象版で確かめた。

| 環境 | 値 |
| --- | --- |
| Pleasanter | `implem/pleasanter:1.5.8.1` |
| DB | `mcr.microsoft.com/mssql/server:2025-CU8-ubuntu-24.04` |
| CodeDefiner | `implem/pleasanter:codedefiner`（`trial /y`） |
| コンテナの OS タイムゾーン | `Asia/Tokyo` |
| API キーの利用者 | `Administrator`（`Language=en`。`TimeZone` は `UTC` と `Tokyo Standard Time` の両方で確認） |

> 検証のスクリプトは `tools/pleasanter-testenv/verify/`。**応答は生のまま `results/` へ出る**（git 管理外）。
> 下の値はその抜粋。

## 1. 日時は「API キー利用者のタイムゾーン」で返る（確定）

同じレコード（`StartTime` に `2026-03-01T09:00:00` を送って作成）を、利用者の `TimeZone` を変えて取得した。

| 利用者の `TimeZone` | `StartTime` | 備考 |
| --- | --- | --- |
| `UTC` | `2026-03-01T09:00:00Z` | **末尾に `Z` が付く** |
| `Tokyo Standard Time` | `2026-03-01T18:00:00` | `Z` は付かない |

- **`Z` は飾りで、時刻は利用者のタイムゾーンの壁時計**。`Z` やオフセットを見て動かさず、書かれている時刻をそのまま
  API キー利用者のタイムゾーンとして読む実装（`EventMapper`）は正しい
- 型付きの日付（`DateHash` の `DateA` など）は `Z` が付かない
- **DB には Pleasanter サーバの OS 時刻で書かれる**（`UpdatedTime` を `KeyValues` の `Value` で取ると `19:43:23` で、
  OS が `Asia/Tokyo` のため。`Text` / 既定では利用者の時刻 `10:43:23Z`）
- **日付だけを入力したレコードを、運用の標準タイムゾーンで 0:00 に読むには、API キーの利用者の `TimeZone` を
  そのタイムゾーン（日本なら `Tokyo Standard Time`）にしておく必要がある。**
  `UTC` の利用者で読むと、同じ「3/5」が `3/4 15:00` や `3/5 09:00` に見え、終日の自動判定（0:00 開始）が効かない
  - 利用者 `UTC` で `2026-03-05T00:00:00` を送って作ったレコードを `Tokyo Standard Time` の利用者で読むと `2026-03-05T09:00:00`
- **API キー利用者の `TimeZone` を変えると全予定の時刻がずれる**（Questionnaire の結果と同じ。1.5.8.1 でも確認）

→ `ApiKeyUserTimeZoneId` は、**API キーの利用者の `TimeZone` と一致させる**。運用手順書へ書く。

## 2. 未設定の日付

- `DateA` など**型付きの日付の未設定は `1899-12-30T00:00:00`**（Questionnaire の結果と同じ。1.5.8.1 でも確認）
- **期限付きテーブルの `StartTime` / `CompletionTime` は未設定にならない。** `StartTime` を送らずに作ると
  **作成した日の 0:00**、`CompletionTime` は**その 7 日後**が入る。「開始が無い予定は出さない」が効くのは `DateX` を開始にした場合だけ

## 3. `ItemTitle` が返り、選択肢の表示名に解決されている

`ClassA` の選択肢を `1,会議` / `2,出張`、サイトの `TitleColumns` を `["ClassA","Title"]`（`TitleSeparator` は半角空白）にしたとき

| `ClassA` | `Title` | `ItemTitle` |
| --- | --- | --- |
| `1` | 時間つき | `会議 時間つき` |
| `2` | 日付だけ | `出張 日付だけ` |
| （空） | 日付なし | `日付なし` |

- **`ItemTitle` は生の値（`1`）ではなく表示名（`会議`）に解決される。** 空の列は詰められる
- したがって件名の既定を `ItemTitle` にしたのは正しい（選択肢・リンクの解決を自前で持たずに済む）

## 4. 完了日（`CompletionTime`）の終了日は包含

`CompletionTime` の列の入力形式を日付のみ（`EditorFormat: Ymd`）にして、`2026-03-06T00:00:00` を送って作成したレコードを取得すると、
**`2026-03-06T00:00:00` が返る**（送った値と同じ。内部では +1 日で保存されるが、API は表示値を返す）。
→ 終日の終了日は包含で、`DTEND` を翌日にする変換が正しい。

## 5. `View.ApiDataType = KeyValues` は日時には使えない（Issue #5）

`GridColumns` に指定した列だけがフラットな JSON で返る。`ApiColumnValueDisplayType` ごとの結果:

| 種類 | 文字・選択肢（`ClassA`） | 日時（`StartTime` / `CompletionTime` / `DateA`） |
| --- | --- | --- |
| `Text`（2） | **`会議`（表示名に解決）** | **`03/01/2026`（ロケール依存・日付だけ。時刻が落ちる）** |
| `DisplayValue`（0） | `会議` | 列によって `03/01/2026`（日付だけ）か `2026-03-01T19:30:00`（時刻つき）。**揃わない** |
| `Value`（1） | `1`（生の値） | **DB の値**（サーバの OS 時刻のまま。`CompletionTime` は +1 日で保存された値） |

→ **日時は既定の `Get`（`ClassHash` / `DateHash` などのある形）から取り、表示テキストが要る文字の列だけ
`KeyValues` ＋ `Text` で別に取って、`IssueId` / `ResultId` で突き合わせる**のが現実的。
`Id` は `Text` でも文字列（`"4"`）で返る。件名だけなら `ItemTitle` で足りるので、この突き合わせは
「任意の列を組み合わせたタイトル」「場所・説明に選択肢やリンクの列を使う」ときだけ要る（Issue #5）。

  `TotalCount` と `Offset` で全ページを辿る現在の実装で足りる
- `CreateSite` の `SiteSettings` に `TitleColumns` / `TitleSeparator` / `Columns[].ChoicesText` / `EditorFormat` を渡せる
- **未確認:** 項目拡張の `Date001`〜`Date100`。`trial` の CodeDefiner では `Date001` を送っても `DateHash` に現れなかった
  （Questionnaire の結果では、項目拡張を既定で有効化するのは `Class` だけ）。拡張列の設定を変えて確かめる必要がある
- **未確認:** リンク・ユーザー・部署の列の表示テキストの解決（`KeyValues` ＋ `Text`）。選択肢の解決だけを確かめた
- Full-Text Search が SQL Server コンテナに入っていないため CodeDefiner が `Full-Text Search is not installed` を
  エラーとして出すが、**この検証には影響しない**（Questionnaire の検証環境と同じ）
