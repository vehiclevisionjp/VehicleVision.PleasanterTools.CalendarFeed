# 機能一覧

本アプリが持つ機能と、方式・設定・関連する Issue / PR の一覧。**実装の単一の参照元は、コードとテストと各手順書**で、ここは入口。
詳しい設計は [`アーキテクチャ方針.md`](アーキテクチャ方針.md)、運用は [`導入-更新運用手順書.md`](導入-更新運用手順書.md)。
Questionnaire の同名の文書に倣った。

## 購読フィード

| 機能 | 内容 | 備考 |
| --- | --- | --- |
| iCalendar の購読フィード | `GET /feeds/{token}.ics`。Pleasanter のレコードを RFC 5545 の予定にする。**読み取り専用** | トークンは 256 bit・DB には SHA-256 だけ。失効・存在しない・形が違うは同じ 404 |
| フィードごとの設定 | サイト ID・列の対応・絞り込み・言語・API キー（フィードごと）・API キー利用者のタイムゾーン | API キーは暗号化して保管し、返さない（末尾だけ） |
| 表示する期間 | フィードごとに、今日から過去・未来へ何日までを出すか（**空は無制限＝開区間**）。**期間と重なる予定を出す**。既定は過去 365 日・未来は無制限。Pleasanter へは日付の列だけ粗く絞り（実機検証結果 12 章）、正確な判定は取得した後 | Issue #67 |
| 表示名の解決 | 選択肢・ユーザー・状況を表示名で出す（`KeyValues` ＋ `Text`） | 実機検証結果 7 章 |
| 文字の列の日付 | 書式を指定して読む | 実機検証結果 8 章 |
| 取得結果の記録 | 最後の取得（成功・失敗の種別・件数）と連続の失敗の回数を管理画面へ出す | Issue #30・#48 |
| CalDAV（読み取り・任意） | カレンダーアプリが直接つなぐ。探索（`/.well-known/caldav` → principal → calendar-home-set）・`PROPFIND`・`REPORT`（calendar-query / multiget）・`GET`。**フィードごとに有効にしたものだけ**が出る（既定は無効）。認証は Basic で、**パスワードは利用者本人の Pleasanter の API キー**（保管しない）。**予定の作成・更新（PUT）ができる**・削除（DELETE）ができる（削除は Pleasanter のごみ箱へ移る）。競合は `If-Match` の ETag で検出（412・428）、UID と名前は DB の対応表に残す | Issue #85。設計は [`CalDAV書き込み-設計方針.md`](CalDAV書き込み-設計方針.md)。運用手順書「CalDAV」 |
| 取得失敗のメール通知（任意） | 連続の失敗が閾値に届いたら 1 通、回復したら 1 通。宛先は `feeds.write` を持つ有効な管理者 | **既定は無効**。Issue #48 |

## 管理者の認証と管理

| 機能 | 内容 | 設定・備考 | 関連（Issue / PR） |
| --- | --- | --- | --- |
| 最初の管理者 | 管理者が 1 人も居ないときだけ作れる（`AdminSetup` の主キーで排他） | 公開する前に作る | #24 |
| パスワードでのログイン | PBKDF2。長さ・ログイン ID と同じ値・正規表現の条件（ReDoS 対策つき）。失敗が続くと締め出す | `CALENDARFEED_PASSWORD_*`・`PasswordPolicies` | #24・PR #37 |
| 2 要素（TOTP） | 登録・復旧コード 10 本（使い切り）・解除（パスワードの再確認つき） | `CALENDARFEED_ADMIN_TWOFACTOR`（`required` / `optional` / `disabled`） | #24 |
| 5 つの役割 | Administrator・FeedAdministrator・UserAdministrator・Editor・Auditor。権限の集合を役割へ割り当てる | 認可は本アプリの DB の役割で行う | #26・PR #39 |
| 招待 | 管理者を招待し、本人がパスワードを決める。招待メール（SMTP / Amazon SES / Azure Communication Services）か、画面の URL を手渡し | トークンは 1 度だけ表示 | #26・PR #39 |
| 管理者の管理 | 役割の変更・無効化・2 要素の解除・端末の失効・棚卸し（長期間ログインしていない人）。**最後の Administrator を守る** | | #26・PR #39 |
| 端末（セッション） | 自分の端末の一覧と失効。管理者が他人の端末を一覧し、1 つずつ失効。**入った方式（パスワード・SAML・Pleasanter）を表示** | サーバ側のセッション（cookie は ID だけ） | #47 |
| 監査ログ | 管理者の操作・ログイン・失敗を残す。保存期間で掃除。絞り込みと、失敗の理由の補足（7 言語） | `CALENDARFEED_AUDITLOG_RETENTION_DAYS` | PR #38・#47 |
| SAML 2.0 でのログイン（任意） | SP。署名・宛先・要求への応答・有効期間を確かめる。自動登録（役割を指定）・単一ログアウト（SP 起点・IdP 起点） | **既定は無効**。`CALENDARFEED_SAML_*`。運用手順書「SAML 2.0 でのログイン」 | #28 |
| Pleasanter のログインで入る（任意） | Pleasanter の cookie をサーバが転送して本人を確かめる。許可する組織・グループ（自動登録の条件）・一定間隔の再検証 | **既定は無効**。同じホスト名での配置が前提。`CALENDARFEED_PLEASANTERSSO_*` | #28 |
| ログインの試行の制限 | IP ごと 5 分に 10 回。**複数台でも同じ枠で数える**（DB の数え） | | #49 |

## 管理画面

| 機能 | 内容 | 関連（Issue / PR） |
| --- | --- | --- |
| 管理画面（Svelte） | フィード・管理者・監査ログ・設定・アカウント。**7 言語**（ja / en / zh / de / ko / es / vi）・ダークモード・スマートフォン幅。**配色・書体（Noto Sans JP・M PLUS 1 Code）・アイコン（Material Icons）は Questionnaire に揃え、アプリへ同梱する**（OFL-1.1。`NOTICE`）。CSP は `default-src 'none'`（インラインのスクリプト・スタイルなし） | #30 |
| アプリケーション設定の編集 | 設定を画面から編集（優先順位は **外部設定 ＞ DB ＞ 既定値**。外部設定にあるものは「固定」）。秘密は暗号化して保管し、返さない。他の台へは 30 秒以内に反映 | #40・PR #41 |
| サーバのエラー文の多言語化 | 管理 API のエラー文を、画面の言語（`Accept-Language`）で返す。7 言語。`Accept-Language` が無い・対応外は `en`。設定の値・SAML と Pleasanter のログインの設定・フィードの列の対応などの動的な検証メッセージも、鍵と埋め込みの値を持つ例外から言語ごとに返す。設定は設定の鍵で示す | #58・#61 |
| 画面の写し | `tools/screenshots` で撮り直せる | [`管理画面-画面の写し一覧.md`](管理画面-画面の写し一覧.md) |

## 運用・基盤

| 機能 | 内容 | 関連（Issue / PR） |
| --- | --- | --- |
| 固定のパラメータ | 運用で調整しうる上限・時間（レート制限・セッション・締め出し・招待・マイグレーションのロック・CalDAV の上限）を、Pleasanter の Parameters に倣った階層・ファイル（`RateLimit.json`・`Session.json`・`Security.json`・`Rds.json`・`CalDav.json`）で。範囲の外は起動時に落とす。**環境変数で指定できる設定は、すべてファイルでも指定できる**（SAML・Pleasanter のログインは `Authentication.json`） | #92 |
| 秘密の鍵の生成 | `--generate-secret-key`（表示）・`--write`（Security.local.json へ書く。すでに鍵があれば断る） | #92 |
| 4 種の RDBMS | SQLite（簡易・デバッグ）/ SQL Server / PostgreSQL / MySQL。Dapper ＋ FluentMigrator。起動時にマイグレーション（複数台でも当てるのは 1 台） | PR #18・#49 |
| 複数台での運用 | セッション・設定・アウトボックス・通知の印・レート制限の数え・マイグレーションのロックを DB に置く。外部の共有基盤は不要 | #49。運用手順書「複数台での運用」 |
| メール送信 | アウトボックス（暗号化・送れたら消す・再送・デッドレター）。応用: 招待・失敗の通知 | #39・#48 |
| 秘密の鍵 | `CALENDARFEED_SECRET_KEY`（AES-256-GCM）。API キー・TOTP の共有鍵・設定の秘密・メールの送信待ち・SAML の相関 cookie を暗号化 | 失うと復号できない（運用手順書 8 章） |
| 信頼するプロキシ | 転送ヘッダは、設定したネットワークから来たものだけ見る | PR #36 |
| CI | ビルドと単体テスト・管理画面・4 RDBMS の結合テスト・**実機（Pleasanter・Keycloak）での通し** | #45 |

## 持たないもの（対象外）

- CalDAV でのカレンダー自体の作成・削除（`MKCALENDAR` など）。カレンダー＝フィードは管理画面で作る
- IdP の属性から役割を引く機能（SCIM・グループ連携）。**認可は本アプリの役割で行う**
- SAML のリクエスト署名（検証用の Keycloak は求めていない。鍵を増やす判断が別に要る）
