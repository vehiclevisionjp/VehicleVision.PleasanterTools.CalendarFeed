## API

以下の経路はすべて `/admin/api` を先頭に付ける。
根拠は `AdminAuthEndpoints.cs:76-78,403-545,632-661` の
`MapAdminAuth`・`TotpBegin`・`TotpComplete`・`ResolveForEnrollmentAsync`
（`src/VehicleVision.PleasanterTools.CalendarFeed.Web/Endpoints/`）。

| 経路 | 要求本文 | 成功時 |
| --- | --- | --- |
| POST `/me/totp/begin` | ログイン後は `{password}`。初回ログイン途中は省略または `{}` | 200 `{secret, uri}` |
| POST `/me/totp/complete` | `{code}` のみ。共有鍵はサーバに預ける | 200 `{recoveryCodes}`（新しい 10 本） |

**ログイン後**は、未登録の任意登録も含めてパスワードを再確認する（Questionnaire と同じ）。
begin が通ると `calendarfeed_admin`（`Session`）を残したまま、
`calendarfeed_admin_reenroll`（`Reenroll`、5 分・延長なし）を発行する。
complete は同じ利用者の両方のセッションとサーバ側の途中鍵を要する。
登録済みの鍵・復旧コードは、begin だけでは変わらない。

**ログイン途中**は、`Required` かつ未登録の場合だけ、
`calendarfeed_admin_pending`（`Pending`）で同じ begin・complete を使える。
登録済みの人の Pending からは、begin・complete とも 401 となり、元の TOTP ログインは引き続き使える。
この初回登録では、追加のパスワード入力や Reenroll を求めない。

| 条件 | 応答 |
| --- | --- |
| Session も対象となる Pending も無い・無効化済み | 401、既存の `loginRequired` |
| 再確認のパスワードが未指定・誤り | 401、既存の `currentPasswordRejected` |
| 締め出し中 | 423、`operationTemporarilyLocked` |
| complete に同じ人の有効な Reenroll が無い | 400、`enrollmentRestartRequired` |
| 途中鍵が無い・数字が不一致 | 既存の 400、`enrollmentBeginRequired` / `totpCodeMismatch` |
| 登録の方針が Disabled（complete 時も判定） | 既存の 403、`twoFactorDisabled` |
| ログイン用の共有枠を超過 | 429、`Retry-After` あり |

エラー本文は本アプリの既存形式 `{error: "要求言語の文言"}` を維持する。
Q の `message` 形式への統一や U4 の状態コード統一は含めない。

## 制限と失効

begin・complete は既存の `RequireAdminLoginRateLimit` を使い、
ログイン等と **IP ごと 5 分に 10 回**の共有枠で数える。
根拠は `src/VehicleVision.PleasanterTools.CalendarFeed.Web/Services/SharedRateLimiting.cs:118-126`。
枠を超えた begin は途中鍵を変更せず、Reenroll も発行しない。
パスワード再確認の誤りは、Q と同じく失敗回数に含める（未入力は数えない）。
5 回目も 401、その次から正しいパスワードでも 423。締め出しは既定 15 分。

完了時は以前の復旧コードを捨て、新しい 10 本を一度だけ返し、Reenroll をサーバ側で失効させる。
通常の Session は残す。初回 Pending からの完了は従来どおり Session へ移る。
再開時は手元の前の Reenroll を失効させる。
ログアウト（SAML の開始を含む）・再ログインでは手元の Reenroll も失効させる。
パスワード変更・管理者の無効化など、既存の全セッション削除も Reenroll に適用される。
Reenroll を Pending・Session の cookie 名に付け替えても、段階の照合で拒否する。

## 画面と確認範囲

アカウントの登録・再登録では、QR を生成する前にパスワードを入力する。
解除と同じ `PasswordConfirmation.svelte` の入力部品、既存の `password` ラベルを使う。
Q の `account.confirmPassword` に対応する案内を本アプリの命名で `accountConfirmPassword` とし、
既存の 7 言語に追加する。再確認後、入力値を消し、通常の登録・復旧コード表示へ進む。
ログイン途中の `EnrollPanel` は従来どおり自動で登録を開始する。

`AdminTotpReenrollTests.cs` と既存の認証・管理者・SSO テストで API の境界を確認する。
フロントエンドは要求本文・経路・423 の文言と 7 言語の整合性をテストする。
実機（Pleasanter・実 DB）での通しとブラウザによる表示確認は未確認。
SQL Server・PostgreSQL・MySQL のストア結合テストは既存の Integration Tests CI に任せる。
